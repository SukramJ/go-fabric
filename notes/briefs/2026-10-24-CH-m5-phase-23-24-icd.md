## 0 What exists and what the bundle changes

- `cluster/core/icd_management.go` is a stateless stub, deliberately not
  mounted (`node/root.go:288-293`); the generated definition
  `cluster/spec/icdmanagement` is complete; RootNode lists IcdManagement
  under `Sit | Lit` (`device/root_node_gen.go:120`). The bridge has no
  Secure Channel opcode 0x50 case (`bridge/securechannel.go:433-440`);
  the controller drops every unsecured opcode but Sigma1 and
  PBKDFParamRequest (`client/exchange/manager.go:790-797`). `store.Port`
  has no ICD area. `client/interaction/sustained.go` is `SustainedSubscription`
  "without the ICD branches"; `client/peer/monitor.go` "the ICD branch
  aside"; `controller/client/properties.go` already reads
  `LongIdleTimeOperating`/`IdleModeDuration`.
- After the bundle: a device built with `node.Config.ICD` is a SIT or LIT
  ICD with a real server, counter, registrations, check-in sender and mode
  machine; the module's controller registers on a LIT peer, receives its
  check-ins, parks its sustained subscription while the peer sleeps and
  re-subscribes when it wakes; the 20 test files are ported; the
  comparison's ICD rows are ✅; the roadmap's done-when for 23 and 24 holds
  ("the module's controller holds a subscription to the module's own LIT
  node across its idle cycles" — one `fabrictest` end-to-end test proves it).

## 1 Phase 23 — the device

- **1.1 Package `icd`** (new, foundation layer beside `secure`/`transport`
  in `archcheck`; no `node`/`bridge` import): the pieces both roles share
  and the device's own, one file per matter.js file, each citing it:
  `icd/checkin` — `Nonce(key, counter)` (first 13 bytes of HMAC-SHA256,
  `CheckInMessage.ts:36-40`), `Encode`/`Decode` (`:45-85`, errors as
  `ErrMalformed` for length < 33 or failed decryption or nonce mismatch),
  `EncodeICD`/`DecodeICD` with the u16 LE active-mode threshold (`:92-115`),
  `ValidateCounter(counter, start, lastOffset)` with the uint32 offset
  arithmetic and `RefreshNeeded` at 2^31 (`:123-136`); `icd.Counter`
  (`IcdCounter.ts`: boot bump 1000 on construction, random seed
  `(rand>>4)+1` when the persisted value is 0, `Increment`/`Advance` with
  wrap and change callback); `icd.ModeState` (`IcdMode.ts:37-152`: Idle/
  Active, `Start/Stop/NoteActivity/RequestActive/EnterIdle`, one timer on
  the injected `clock.Clock`, the three callbacks, no automatic
  active→idle; windows never shorten); `icd.DoublingBackOff`
  (`IcdCheckInBackOff.ts:38-84`); `icd.MonitoredSubjectCovered` and the
  subscription-subject view (`IcdCheckInSuppression.ts`); `icd.Registration`
  and the device-role registration table (`FabricIcd.ts:45-60`).
- **1.2 The server** replaces the stub in `cluster/core/icd_management.go`
  (not an owner file): features from config (CIP default; LITS, UAT, DSLS
  opt-in), `initialize` validation as `IMS:184-229` (idle ≥ active;
  maxBackoff ≥ idle; LITS needs CIP; LITS needs threshold ≥ 5 s; UAT hint
  bits that need an instruction), attributes with the schema defaults
  (`icd-management.element.ts:31-69`), `RegisterClient` (slots
  `ResourceExhausted`, Administer bypass, `VerificationKey` mismatch →
  `Failure`, returns the counter, `IMS:551-602`), `UnregisterClient`
  (`NotFound`, `IMS:705-730`), `StayActiveRequest` (floor
  `min(30 s, requested)`, `IMS:607-624`); `OperatingMode` derived from
  registrations (`IMS:462-472`), forced by DSLS (`:666-700`);
  `RegisteredClients` fabric-scoped, keys outside the attribute struct
  (`IMS:787-791`); the counter persisted on every change; `fabric removed`
  clears keys and registrations (`IMS:525-542`). Persistence: a new
  `store.ICD` area (registrations per fabric with key, the counter) in
  `store.Port`, SQLite + `store/memstore`, `storetest` cases; the memstore
  cascade on fabric removal.
- **1.3 The check-in sender** (`IcdCheckInSender.ts`, `IMS:356-445`): per
  idle→active wake, for every fabric's permanent registrations not covered
  by an active subscription of the monitored subject (the bridge's
  `im/subscription` manager knows sessions per fabric — read
  `im/subscription/manager.go` and `bridge/subscribe.go` for the view), by
  the back-off, encoded with the registration's key and `counter.Increment()`,
  sent **unsecured** (session 0, opcode 0x50 — add `mrp.SCOpcodeIcdCheckIn`
  to `transport/mrp/ack.go`) to the peer's operational address resolved
  over mDNS (`mdns/operational_resolver.go`; the bridge's
  `sendInitiatedUnsecured` seam at `bridge/case_initiator.go:379-424`
  generalised to a bridge method the sender gets as a function; no MRP
  retransmission, no ack, best effort). Failures are logged, never
  returned to the mode machine.
- **1.4 Facade.** `node.Config.ICD *node.ICDConfig{Mode (SIT|LIT), IdleModeDuration,
  ActiveModeDuration, ActiveModeThreshold, ClientsSupportedPerFabric,
  UserActiveModeTrigger{Hint, Instruction}, DynamicSITLIT bool}` (nil = not
  an ICD, nothing mounts, nothing changes); `Node.ICD()` with
  `RequestActiveMode`, `EnterIdleMode`, `TriggerUserActiveMode`,
  `SetOperatingMode`/`WithdrawForcedOperatingMode` (DSLS), `Mode()`,
  `OnModeChange(fn)` (inline + `Async` on the node's callback rule for the
  three events); the server mounts on the root under `Sit | Lit` only
  with the config, and the device-type validator sees the stated
  condition. Side effects as matter.js: MRP local backoff padded by the
  fast-poll interval 200 ms while an ICD (`IMS:53, :257` — the bridge's
  session parameters), mDNS `ICD` TXT key and no SII for LIT
  (`IMS:482-495`; `mdns/service.go:259-263` has the field), subscription
  persistence off on an ICD node (`IMS:234-236`), `fabric removed` hook.
  `node.Config.Validate` refuses the same combinations `initialize` does,
  with `ErrInvalidConfig` naming the field.
- **1.5 Tests.** Port the eight phase-23 files (map §3.1/3.2) in the
  phase-18 pattern (file header, `t.Run` titles verbatim, register →
  `ported`/`partial`, ratchet): `IcdManagementServerTest` through
  `fabrictest` (a device with `Config.ICD`, a controller registering;
  Administer vs Manage via `Pair.Grant`), `IcdModeTest`, `CheckInMessageTest`
  with its vectors, `FabricIcdTest` device role (controller role in §2),
  `IcdCheckInBackOffTest`, `IcdCheckInSenderTest`, `IcdCheckInSuppressionTest`,
  `IcdCounterTest`; `ServerSubscriptionTest`'s LIT-interval part
  (register entry reason at `register.json:2815`) moves from missing to
  covered. The ICDM/ICDB chip-tool families are not run (no ICD in the
  reference bridge); the YAML cases are classified under
  `docs/certifiability.md` as "not applicable to the reference daemon;
  applicable to a host that sets Config.ICD" — read how other families are
  classified there.

## 2 Phase 24 — the controller

- **2.1 Receive path.** `client/exchange/manager.go` `handlerFor`: an
  unsecured opcode 0x50 goes to a registered check-in receiver (a new
  `SetCheckInReceiver(fn)` on the manager, as `SetProtocolHandler`), no
  response, exchange closed (`SecureChannelProtocol.ts:149-180`).
- **2.2 `icd` controller role** (same package): `icd.PeerTable`
  (`FabricIcd.ts` controller role: peers with key/pendingKey/counterStart/
  lastOffset, trial decryption current then pending, replay drop, pending
  promotion with the modulo baseline, `ConfirmKey`, `RefreshNeeded`,
  `ProcessCheckIn` returning whether a peer matched; `:66-272`),
  `icd.PeerSchedule` (`IcdPeerSchedule.ts`: margin 10 s, default timings,
  active for the longer of threshold and duration, next check-in due),
  `icd.PeerWakefulness` (`IcdPeerWakefulness.ts`: awake/available,
  `AwaitAwake(ctx)`, `HoldSubscription`, `RequiresAwait`, suspend/resume/
  close, the two timers on the injected clock, `CheckInMissed` callback).
- **2.3 The ICD client on `controller/client.Node`** (`IcdClient.ts`,
  map §2.4): `Register(ctx, opts)` (single-admin guard with the trusted
  vendors Apple 0x1384, SmartThings 0x110a, OHF 0x134b and `AllowMultiAdmin`;
  16-byte random key; `RegisterClient` on the peer; commit key/counterStart/
  lastOffset/monitoredSubject/clientType into the node's record —
  `controller/client/record.go` and its store, nonvolatile fields as
  `IcdClient.ts:1039-1101`), `Unregister` (awaits the peer awake, clears
  locally, `UnregisterClient` with the verification key), `Forget` (local
  only), `StayActive(d)`, auto-registration on a LIT-operating peer with
  an active subscription (`#ensureLitRegistration`, `#autoRegister`:
  `litSupported` = LITS feature + specification version ≥ 1.4.0,
  `OperatingMode == Lit` read fresh, DSLS peer with registrations), key
  refresh when `RefreshNeeded` (`#offerKey`/`#refreshKey`: pending key,
  `RegisterClient` with verification key, `ConfirmKey`), one in-flight
  operation with the take-over table (`:947-952`), the receive path
  restored on start from the record, decommission → local clear and
  peer removed; events `OnCheckIn`, `OnRegistered/Unregistered`,
  `OnCheckInMissed`, `Available()`, `NextExpectedCheckIn()`. The
  `Properties()` of the node gain `IsLongIdleTimeOperating`
  (`ClientNodePhysicalPropertiesIcdTest`).
- **2.4 Hold until awake.** `client.Node.Read/Write/Invoke` on a
  LIT-operating registered peer wait for the wakefulness (`holdUntilIcdPeerAwake.ts`:
  default timeout = `nextCheckInWithin`, per-call override, abort →
  `ErrPeerAsleep` naming the peer and the timeout; `ClientNodeInteraction.ts:87,
  :194, :219, :333-346`); a non-LIT or awake peer passes through.
- **2.5 The parked sustained subscription** (`client/interaction/sustained.go`
  gains the ICD branches of `SustainedSubscription.ts:116-337`, map §2.5):
  a wakefulness provider and a `peerFed` signal in the request; while
  `RequiresAwait` and asleep, park instead of retrying (no timed retry,
  `:246-256`); hold the wakefulness while subscribed (`HoldSubscription`);
  on a mode flip tear down and recreate; the "icdLit priority network" is
  a connect option (`client/peer.ConnectOptions`) since the module has no
  network profiles (by_design `NetworkProfileTest`) — say so. The address
  monitor's ICD branch (`PeerAddressMonitor.ts:143-168`: a sleeping LIT
  peer is never probed; a changed mDNS address is adopted on trust) in
  `client/peer/monitor.go`. The MRP idle-interval floor for a LIT peer
  when no source gives an SII (`IcdClientTest.ts:2657-2690`; read
  `controller/client/properties.go:292-295`).
- **2.6 `RebootResubscribeArmer`** (`RebootResubscribeArmer.ts`): the
  type and its 25 cases in `client/peer` (sessions added, report started,
  grace 30 s, return timeout `min(max(delay,0),24h)+3min`, `Arm/Disarm`,
  recover a silent peer); the call site is phase 25's OTA push — this
  bundle wires it to a public `Arm` the OTA provider path calls later and
  says so in the report.
- **2.7 Tests.** Port the twelve phase-24 files (map §3.1/3.2; the
  register entries are `excluded`/`controller-stage` and become
  `ported`/`partial` with the class removed — read `script/testparity/register.go`
  for what a class change needs): `IcdClientTest` (2 764 lines, 90+
  cases: port the register/unregister/forget/stayActive/auto-register/
  check-in/key-refresh/availability/decommission/routing groups; the
  "ICD state held by another transaction" group has no Go subject — the
  Go node has no transaction model — skip with one reason), `IcdMultiAdminErrorTest`,
  `IcdPeerAsleepErrorTest`, `holdUntilIcdPeerAwakeTest`, `litSupportedTest`,
  `ClientNodeInteractionIcdTest`, `ClientNodePhysicalPropertiesIcdTest`,
  `IcdPeerScheduleTest`, `IcdPeerWakefulnessTest`, `RebootResubscribeArmerTest`,
  `FabricIcdTest` controller role, `SustainedSubscriptionTest` ICD part
  (`partial` → wider; update the reason). `PeerConnectionSocketOwnershipTest`
  stays phase 25 (TCP).
- **2.8 The end-to-end proof** (`node/icd_e2e_test.go` or in `fabrictest`'s
  own tests): a LIT device (`Config.ICD`, idle 30 s fake time) and a
  controller: commission, subscribe (sustained), the client auto-registers,
  the device enters idle, a read parks and completes on the check-in, the
  subscription survives three idle cycles, `Unregister` ends it. On the
  fake clock, paced by `Site.Step`/`Eventually` (CG's model).
