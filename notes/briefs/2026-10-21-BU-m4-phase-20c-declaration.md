## BU-a — the code

### 1 One declaration (G1-4; ADR 0025 P2, P3)

- Per generated cluster package a value type `<cluster>def.Declare`
  (generated by `script/clustergen` next to `State`/`Patch`): `Initial
  Patch`, `Features <cluster>def.Features` (the selection; zero = the
  device type's default), `OnWrite` (the controller-write veto of BT),
  `Handle<Command>` fields (one per command, the typed handler; nil =
  the server's own), `Transitions bool` where the cluster has them
  (LevelControl, ColorControl), and the server's host ports as typed
  fields where the self-held server needs one (the lock's actuator, a
  mover, a measurement source, a mode changer — the ports BX1 listed
  under "stub, needs a host port": the declaration carries the port and
  the kit's default becomes the self-held server once the port is
  declared; the port fields take the **generated** request/state types,
  so `LevelSource`/`Stepper`'s `cluster/wire` forms are deprecated with
  the window — BX1 question 1). `Declare` implements `device.Declaration`
  (`ClusterID() uint32` and an unexported apply) and `device.New<Type>`
  takes `...device.Declaration` beside `device.Options`. `WithInitial`,
  `WithFeatures`, `WithElements`, `WithServer` stay (README window,
  `Deprecated:` with the replacement) and are implemented through the
  declaration, not beside it. `device.Options.Clock` is deprecated: a
  device takes the node's clock when it is added (G1-4's sixth pair).
- `lock.New`: an empty feature selection means none (BX1 question 2);
  a DoorLock device without features mounts the self-held lock once the
  declaration carries its actuator. Announced break (CHANGELOG, v0.10.0).
- **The declaration as data** (`device.FromSpec`): `device.Spec{Type
  schema.DeviceTypeID, Options, Declarations []Declaration}` and
  `device.FromSpec(Spec) (*Device, error)` — the generic constructor
  every `New<Type>` is a one-line wrapper of (`device.NewOfType(id, …)`
  if a name is needed). A host whose devices come from a config file
  builds a `Spec` per device; nothing in it is reflective. One table
  test over every snapshot device type: `FromSpec` with the type's
  default selection equals `New<Type>`.
- Tests: `device/declare_test.go` (every field of `Declare` observable
  over `fabrictest`: Initial read back, Features in the FeatureMap,
  OnWrite vetoes a controller write, a `Handle` replaces a command, a
  declared port receives the command); the G1 consumer's bridge
  (`notes/briefs/reports/G1-consumer/bridge.go.txt`) rewritten on the
  declaration is `node/declaration_consumer_test.go` — the acceptance
  test in spirit: no `Underlying`, no `WithServer`, no second way.

### 3 The callback rule and the change's origin (G1-10; ADR 0025 P8)

- Every facade callback (`OnChanged` typed and `Device.OnChanged`,
  `OnWrite`, `Handle<Command>`, the declaration's ports) runs inline on
  the event's goroutine, before the response. Each has an `…Async`
  variant (`OnChangedAsync`, …) that queues on **one serial goroutine
  per device**, owned by the device, started at Add and stopped —
  waited for — at Remove/`Node.Stop` (ADR 0026 P5). One sentence in
  `docs/guides/concurrency.md`, the same for every callback.
- The typed `OnChanged` reports the origin: `OnChanged(func(State,
  Change))` with `Change{Attributes []uint32; Origin Origin}` and
  `Origin` ∈ {ControllerWrite, Command, HostSet} (`device.Device.OnChanged`
  the same). BT's `changed []uint32` signature changes with it — allowed:
  BT and BU ship together in v0.10.0 (owner, 2026-10-20); CHANGELOG
  `### Changed`. Where the origin is derived in the chain
  (`contract.AttributeChangeNotifier` → hull), say in the report how it
  is carried without a second notifier interface.
- Tests: origin per path (a controller write, a command, a host `Set`),
  inline order (the callback ran before the response left), the Async
  queue drained at Stop.
