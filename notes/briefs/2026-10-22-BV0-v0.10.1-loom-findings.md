## 1 #225 — the 32-bit build

`node/credentials.go:54`: clamp through `int64`
(`v := int64(c.PBKDFIterations); if v < 0 {v = 0}; if v > math.MaxUint32 {v = math.MaxUint32}; iterations := uint32(v)`),
no `nolint`. Guard: a CI job `build (32-bit)` in `.github/workflows/ci.yml`
running `CGO_ENABLED=0 GOOS=linux GOARCH=arm GOARM=7 go build ./...` and
`GOOS=linux GOARCH=386 go vet ./...` (vet type-checks the tests too),
plus `make build-32bit` in the Makefile and `make help`; `go build
-gcflags=-e ./...` for both targets must print nothing. CHANGELOG
`### Fixed`.

## 2 #222 — `NativeMover` and every port on the generated requests

`cluster/levelcontrol/native.go:55` `MoveLevel(ctx, req wire.MoveRequest, withOnOff bool)`
→ `levelcontroldef.MoveRequest`; grep every exported port method of the
self-held servers for a `cluster/wire` parameter or result type
(`grep -rn 'wire\.' cluster/*/ --include=*.go | grep -v _test | grep -E 'func .*\(.*wire\.'`)
and move each to its generated form; the `wire` level and fan-step
request types stay only where an engine uses them internally — if no
use is left, they go (migration-guide line). CHANGELOG `### Changed`,
guide row.

## 3 #220 — `device.HostServer(srv)`

A host whose servers are a list gets one name: `device.HostServer(srv
contract.ClusterServer) Declaration` — resolves the server's
`MatterClusterID()` to its generated declaration (a table written by
`script/clustergen` or `script/devicegen` into `device/hostserver_gen.go`:
cluster id → `func(contract.ClusterServer) spec.ClusterDeclaration`,
one line per generated package; regenerate, never hand-write) and
returns `<cluster>def.Declare{HostServer: srv}`'s declaration; for a
cluster id without a generated package it is `WithServer`'s mount (the
manufacturer-specific path), so a host needs no second form. Doc
comment says when to prefer the typed `Declare` (ports, Initial). Tests:
loom's shape — a list of ten servers over `HostServer`, the device
mounts each, `go doc` shows one route; a server whose id has no package.
CHANGELOG `### Added`, guide row ("`WithServer(srv)` for a list →
`device.HostServer(srv)`").

## 4 #221 — the kit's form for a classified measurement source

`device.Measurement(src contract.MeasurementSource) Declaration` (name
it after the kit's style): the kit materialises the source through
`cluster/measurement` at add time, when the endpoint number is known
(read `cluster/measurement/materializers.go:128-176` and
`endpoint/materialize.go:81-84`: the same materialiser the endpoint
assembler runs), so the momentary switch and the battery work, and the
device keeps device-type validation and the mandatory client clusters.
`endpoint.Spec.Measurement` stays as the seam; the guide's row for
`WithMeasurement` names the new form and, for a host on the endpoint
seam, what it loses. Tests: every built-in measurement class over the
kit on `fabrictest` (read → the class's attribute), the switch and the
battery included. CHANGELOG `### Added`.

## 5 #223 — the validator's route (docs)

`docs/guides/migrating-to-the-facade.md` and `docs/guides/advanced-seams.md`:
a validator that runs without a node (a config package, a CLI) imports
`secure/setup` (`ValidateSetupPIN`, the discriminator bound) and
`secure/spake2` (the PBKDF bounds) directly — the two leaf packages with
no stack behind them — and `node`'s re-exports are for the host that
builds the node; state the measured cost loom saw (18.4 MB → 32.4 MB)
as the reason in one sentence. No API change.

## 6 #224 — the guide's three gaps

- DoorLock: the "Changed" section and "What a migrating host meets"
  say that an empty feature selection is none since v0.10.0 and a lock
  that relied on Unbolting declares `Features: lock.FeatureUBOLT`
  (check the constant's name).
- Store on a shared handle: `advanced-seams.md`'s store row names the
  tables the schema gained since v0.6.0 (`matter_thermostat_presets`,
  schema v5; the three `matter_doorlock_*` tables, v6 — read
  `store/` migrations for the exact names and versions) and that a host
  carrying the schema in its own migrations adds them.
- The worked example's pin: loom was at `v0.7.3` when it migrated —
  say which pin the table was checked against and that the cited lines
  held.
