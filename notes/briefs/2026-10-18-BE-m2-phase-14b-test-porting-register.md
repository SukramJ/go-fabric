## Items

1. **The snapshot** `script/testparity/matterjs_tests.json`, written by
   `go run ./script/testparity -snapshot` (`MATTERJS_DIR`, default
   `../matter.js`; the commit from `parity/schema.json`): every `*Test.ts`
   under `packages/node/test` and `packages/protocol/test` with path, line
   count, SHA-1 of the blob (`git ls-tree` gives it), and the top-level
   `describe("…")` names. Sorted, stable. Exit 2 without the clone or the
   commit. Expected: 324 files (210 + 114).
2. **The register** `script/testparity/register.json`: one entry per
   snapshot path — `status` ∈ `ported` | `partial` | `planned` | `excluded`;
   `go`: `["<pkg path>:<TestFunc>", …]` for `ported`/`partial`; `missing`:
   the `it(…)` names not covered, for `partial`; `class` for `excluded` from
   exactly `controller-stage` (+ `until`), `js-runtime-only`, `joint-fabric`,
   `device-ble-thread`, `test-infrastructure`; `reason`: one sentence;
   `snapshotSha`: the blob SHA-1 the mapping was checked against. A Go type
   with validation (unknown status or class, `go` on an `excluded`, missing
   `reason`) and a JSON schema comment in the package doc.
3. **The page** `notes/parity/matterjs_tests.md`, generated by
   `go run ./script/testparity -render`: header (pin, counts per status),
   one table per directory in tree order (`file | lines | status | Go tests
   or class | note`), then the `planned` list grouped by directory. Marked
   generated at the top; `make testparity` regenerates snapshot-independent
   (render only), `make testparity-snapshot` refreshes the snapshot.
4. **The guard** `script/testparity/register_test.go`: every snapshot path
   has an entry and every entry a path; every `go` reference resolves,
   through `go/parser` on the named package's `_test.go` files, to a
   `Test…` function that exists; a `ported`/`partial` whose `snapshotSha`
   differs from the snapshot fails with "re-check the mapping"; rendering
   the page reproduces the committed file byte for byte; the constant
   `testparityPlannedRatchet` equals the `planned` count exactly, in both
   directions, documented like `reachabilityUnreachedRatchet`. Makefile
   `testparity-check` runs the test; CI job `testparity` runs it without a
   matter.js clone.
5. **The initial fill.** For every file decide from the seed, then confirm
   against the sources — slices, not files: the matter.js file's `describe`
   and `it` names (`git show … | grep -n '^\s*\(describe\|it\)('`), and the
   candidate Go tests' `func Test` names and `t.Run` names. `ported` only
   when the Go tests cover the `it` cases semantically; otherwise `partial`
   with `missing`. `excluded` only with a class from the list: controller
   behaviour we do not have yet (`controller-stage`, `until` the roadmap
   milestone), tests of JS runtime concerns (`js-runtime-only`: observables,
   environment, plugins, storage caches, the `Reactor`), Joint Fabric,
   device-side BLE/Thread (`device-ble-thread`, until M7), tests of test
   helpers (`test-infrastructure`). Everything else is `planned`. Record
   the counts per status and per directory in the report; the owner reviews
   every `excluded` and a ten-percent sample of `ported`.
6. **Docs and CHANGELOG.** `docs/matter-parity-contract.md` gets the
   register as a guard row; `docs/roadmap.md` is the owner's. One CHANGELOG
   entry.
