# Gate 1 — architecture audit of phase 20 (ADR 0025 + ADR 0026)

Date 2026-10-20 (runs after #197 BS and #198 BT merged). Owner decision:
gate 1 is a whole-tree audit, findings fixed in their own wave before BU.

## Three parts, one report (`notes/briefs/reports/G1.md`)

1. **Inventory (Sonnet, `notes/briefs/reads/read-gate1-inventory.md`)** —
   a map with `file:line`, no judgement:
   - §1 import graph: `script/archcheck` result; every edge into `im`
     from `cluster/*` with the identifier used (status errors,
     `FabricFilterFromContext`, …); `cluster/core → groups`,
     `groups → cluster/spec`; `controller/client → device, endpoint` with
     the identifiers; `binding → controller/*` identifiers.
   - §2 goroutines: every `go ` statement in non-test code with its owner
     type, how it is stopped (context, done channel, WaitGroup) and
     whether `Stop`/`Close` waits for it; every `time.AfterFunc`/`NewTimer`
     not on `clock`.
   - §3 locks: every `sync.Mutex`/`RWMutex` field with the comment naming
     what it protects (or "no comment"); every place a lock is held while
     calling a callback/host hook or doing I/O (grep for `.Lock()` …
     `fn(`/`Write`/`Send` before `Unlock()` within a function).
   - §4 time and randomness: `time.Now`, `time.After`, `time.Sleep`,
     `time.NewTimer`, `time.Tick` in non-test code; `rand.Read`/`crypto/rand`
     call sites and their test seams.
   - §5 errors: `errors.New("<prefix>:` prefixes per package versus the
     package name; typed errors; places that format an IM status by hand
     (`fmt.Errorf("... status ...")`) outside the dispatcher; the
     dispatcher's text heuristic (`endpoint/dispatcher.go`, "constraint").
   - §6 logging: `slog` event names not in dotted lower case; `fmt.Print*`
     and `log.` in non-test code; components without an injected logger.
   - §7 persistence: every `os.Open/Create/WriteFile`, `sql.Open` outside
     `store`, `endpoint/sqlitestore`, `controller/client/sqlstore`,
     `node/store_path.go`, `bdx` (downloads) — with the reason visible.
   - §8 facade surface: `go doc -all ./node ./device ./contract` exported
     identifiers whose types come from a lower package without an alias
     (`Config.DeviceTypeValidation`, `Node.Peers`, `Node.Bindings`, …);
     identifiers using matter.js-internal vocabulary (behavior, agent,
     transaction, backing).
   - §9 tests: packages without a `*_test.go`; test runtime per package
     from one `go test -json ./...` run (top 15); flaky tests known
     (`TestRegistryDecommission`, `TestLiveSustainedSurvivesRestart`,
     `TestNodeLifecycleSeededPairParity`, `TestNetworkLossAndDelay`,
     `TestDiagLogsBDX_Transfer`, `TestOtaParityMatterJS`): file:line and
     what each waits on.
2. **The consumer (Opus, fresh context, read-only worktree at main)** —
   receives only: `go doc -all ./node ./device ./contract`,
   `docs/getting-started/*.md`, `docs/guides/*.md`, and the task "write a
   bridge for two devices (a dimmable light whose level the program
   changes every second and a contact sensor) as a Go program against
   this module, with a `fabrictest` test that commissions it and reads
   both; note every point where you had to guess, could not find a name,
   or found two ways to do one thing". Its notes are findings against
   ADR 0025 principles 1, 2, 5; its program is kept under
   `notes/briefs/reports/G1-consumer/` as evidence, not merged into
   `examples/`.
3. **The judgement (Fable)** — one section per principle of ADR 0025
   (12) and ADR 0026 (12), each: the evidence from §1–§9 and the
   consumer's notes, the finding (or "holds"), the fix and its wave.
   Findings are numbered G1-1…; each names the principle, the package,
   the file:line and the size of the fix (lines, a refactor, an ADR
   change). Known candidates going in: binding → controller/* (0026 P1,
   P12: move the client stack to a role-neutral `client/` tree?);
   cluster/* → im for statuses (0026 P8: an `im/status`-free status type
   below the servers, or accept with the reason); cluster/spec under
   cluster/ (0026 P1: `cluster/spec` is model — move to `spec/`? a large
   rename under the window); controller/client → device/endpoint (0026
   P12); time.Now residues (0026 P4); aliases vs interfaces for
   `SessionManager`/`SubscriptionManager` (0025 P3); lower types in
   `Config.DeviceTypeValidation`, `Node.Peers`, `Node.Bindings` (0025 P3);
   `Get()` zero on a type mismatch (0025 P7); the hull's reflection
   conversion vs generated per-field code (0026 P10); flaky tests and
   `node`'s race runtime (0026 P5, P10); `Fabrics()` deprecation path;
   the dispatcher's "constraint" text heuristic (0026 P8).
4. **The fix wave (BX)** — a brief from the findings the owner accepts
   (wizard: which findings now, which at gate 2, which become an ADR
   change); one Opus agent, or two on disjoint paths; `v0.9.2` is not a
   tag (owner decision: BT + BU + fixes = `v0.10.0`).

## Order

Inventory and consumer run in parallel on the merged main (after #198);
the judgement follows; the owner reads the report and decides the fix
wave in a wizard; BX runs; then BU.
