## Mediums (each a commit; the finding ID in the commit title)

1. **W4-ctlnet-01** — `client/exchange/margins.go:59` and
   `client/exchange/exchange.go:607`: the additions to a saturated
   `mrp.BackoffDuration` wrap negative; add with saturation (one helper in
   `margins.go`) or cap before adding; matter.js `MRP.ts:182-190`,
   `MessageExchange.ts:1242-1250`. Tests: transmission 60 with
   `InitialRetransmissionTime = 2 min`, and with `LocalFixedMrpBackoff > 0`.
2. **W4-ctlnet-02** — `client/exchange/manager.go` `route` (`:793-857`): a
   message that opens a new exchange on a secure UDP-bound session
   (`s.channel == nil`) from another address moves the session to it
   (`s.SetAddr(src)`), and the peer's `followAddress` is told so the
   descriptor follows; no move inside an existing exchange; matter.js
   `ExchangeManager.ts:425-431`; the device side already does it
   (`bridge/receive.go:159-161`). Test: a report from a new address is
   acked at the new address.
3. **W4-ctlim-01** — `controller/client/structure.go:243-251`,
   `node.go:288-292`, `network.go:301-307`: `Hooks.Event` and the
   persisted event cursor move only for the default subscription's
   reports while it is current, its bootstrap read and the
   newly-commissioned read (`emitEvents`); every other interaction returns
   its events in the `Report` only; matter.js `ClientStructure.ts:412,
   :1757-1758, :1770`, `ClientNodeInteraction.ts:97-98`,
   `NetworkClient.ts:171-173, :303-308`. Test: a host `Node.Read` with an
   event path neither calls `Hooks.Event` nor raises the cursor.
4. **W4-ctlim-02** — `client/interaction/invoke.go:171`, `write.go:225`,
   `invoke_batcher.go:56-60`: a timed invoke is inferred from
   `schema.IsTimedInvoke` (OR-ed into `timed` and into `batchable`), a
   timed write from the attribute's timed access quality — add
   `schema.IsTimedWrite(clusterID, attributeID)` next to `IsTimedInvoke`
   (`schema/timed.go`, built the same way from the snapshot, with its
   snapshot test); matter.js `Invoke.ts:136-139, :237`, `Write.ts:188`,
   `ClientInteraction.ts:200`. No opt-out field unless a test in the
   module needs one (then additive, `TimedOff`-style, cite matter.js's
   `options.timed === false`). Tests: DoorLock LockDoor with zero options
   sends a TimedRequest first and stays out of the batch; a timed
   attribute write likewise.
5. **W4-ctlim-03** — `controller/client/registry.go:439-446` `deleteNode`:
   close the host's active subscriptions for the peer (the node
   interaction's `CloseSubscriptions()` as `Node.Disable` does,
   `node.go:504-506`), not `CloseForPeer` (which re-establishes); matter.js
   `ClientNode.ts:291-300`, `ClientInteraction.ts:264-282`. Trace what the
   sustained retry does after `peer.Delete` and state it in the report.
   Test: a `Sustain: true` subscription to a deleted node is closed, not
   retried.
6. **W4-ctlim-04** — `client/interaction/report.go:489→510`: the final
   StatusResponse must not wait for store writes and host hooks. Apply the
   cache under the lock in `consume`, hand emissions, store writes and
   hooks to a per-node ordered worker bounded like matter.js's
   `MAX_PENDING_JOBS = 100` (`ClientStructure.ts:57, :417-439, :469`;
   `InteractionMessenger.ts:1020-1045`). Ordering per node is kept; the
   worker drains on `Node.Stop`/`Close`. CHANGELOG states that hooks now
   run off the report exchange. Test: a blocking `Hooks.Changed` does not
   delay the StatusResponse.
7. **W4-ctlint-03** — `controller/softwareupdate/images.go:212-235` `Store`:
   `otaimage.ValidateFile` (payload digest and size; the full checksum when
   `info` carries one) before `Put`, refused as `ErrOTA`; matter.js
   `DclOtaUpdateService.ts:573-574, :388-424`, `OtaImageReader.ts:65-110,
   :246-278`. Test: a truncated local image is refused.
