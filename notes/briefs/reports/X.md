## What was built

### 1. `contract.DeviceTypeName` covers every snapshot device type (#57)

- Generator: **`script/devicegen`**, not `script/generate_matter_schema.go`.
  The latter writes only into `schema/`, a package that is generated end to
  end; devicegen already writes `_gen.go` files into an otherwise
  hand-kept package (`device/`) and carries the staleness guard pattern
  (`TestCommittedFilesAreCurrent`) the brief asks for. `make
  generate-matter-schema` already runs it, so a snapshot refresh
  regenerates the table with no Makefile change.
- `script/devicegen/labels.go`: `generateContractNames` writes
  `contract/devicetype_names_gen.go` — `var deviceTypeNames
  map[uint16]string` over every snapshot device type with an id (91), by
  id; an id above 0xFFFF is an error. `labelOverrides` keeps the
  hand-kept spelling where it differs from the matter.js name, one
  comment per entry; the generated line carries the matter.js name as a
  comment. `run` gained `-contract-out` (default: `-out` if given, else
  `contract/`).
- `contract/matter.go`: the hand-kept map is gone; `DeviceTypeName`'s doc
  says where the table comes from. `contract/` still imports stdlib only
  (the generated file imports nothing).
- Review item — the diff of the generated table against the old map:
  25 of the 31 hand-kept labels differ from the matter.js name and are
  overrides: Door Lock (DoorLock), Generic Switch, Contact Sensor, Mode
  Select, Air Quality Sensor, Air Purifier, Water Leak Detector, Laundry
  Washer, Robotic Vacuum Cleaner, Smoke / CO Alarm (SmokeCoAlarm),
  Extractor Hood, Laundry Dryer, On/Off Light (OnOffLight), Dimmable
  Light, Light Sensor, Occupancy Sensor, On/Off Plug-in Unit
  (OnOffPlugInUnit), Color Temperature Light, Extended Color Light, Window
  Covering, Temperature Sensor, Pressure Sensor, Flow Sensor, Humidity
  Sensor, Electrical Sensor (ElectricalSensor). Six are identical and need
  none: Speaker, Fan, Dishwasher, Closure, Thermostat, Pump. The 60 new
  entries carry the matter.js name verbatim (`SoilSensor`, `RootNode`,
  `OtaRequestor`, …).

    `TestDeviceTypeNameCoversEveryMeasurementClass` — every built-in

    `DeviceTypeName(0x0045) == "SoilSensor"`. Fails with the SoilSensor

  - `TestDeviceTypeNameNamesTheApplicationDeviceTypes` now pins all 31

### 2. `store.Migrations()` and `store.SchemaFingerprint` (#62)

- `store/migrations.go`: `type Migration struct { Version, Up, Down
  string }`, `func Migrations() []Migration`, `func
  SchemaFingerprint(ctx, db) (string, error)`. The step texts are embedded
  files `store/migrations/v{1..4}.{up,down}.sql`.
- The cut (see open question 1 — it differs from the brief):
  - `v1` — v0.1.0: the DDL v0.1.0 shipped (`git show
    v0.1.0:store/schema.sql`, comments removed); `matter_group_key_map`
    with its foreign key into `matter_group_keys`.
  - `v2` — v0.2.0: `matter_group_table`, `matter_groupcast_groups`,
    `matter_server_subscriptions` + `matter_server_subscriptions_fabric`
    (statements are `schema.sql`'s).
  - `v3` — v0.2.0: the `matter_group_key_map` rebuild without that foreign
    key. `Upgrade`'s `dropGroupKeyMapKeySetForeignKey` now executes this
    same embedded text in its transaction (one source).
  - `v4` — v0.3.0: `matter_ota_default_providers`.
  - Downs: `DROP TABLE IF EXISTS` for v1/v2/v4 (children first in v1); v3's
    Down is the reverse rebuild with the foreign key, dropping entries
    whose key set does not exist (they cannot satisfy the key) — lossy,
    documented in `v3.down.sql`, on `Migration.Down` and in the CHANGELOG.
- `Schema()`, `Apply`, `Upgrade` keep signatures and behaviour;
  `schema.sql` stays the flattened form.
- `SchemaFingerprint`: SHA-256 hex of sorted `type|name|tbl_name|sql`
  rows of `sqlite_schema` restricted to the tables and named indexes the
  embedded DDL declares (read from `schema.sql` by name, no hard-coded
  list — owner fix-up f2cf782) plus those tables' automatic
  `sqlite_autoindex_<table>_N` indexes, the sql normalised (identifier quotes
  dropped, whitespace collapsed, none beside `(`, `)`, `,`). The
  normalisation is needed because `ALTER TABLE … RENAME` rewrites the
  stored statement as `CREATE TABLE "matter_group_key_map"`. Host tables
  (including `endpoint/sqlitestore`'s `matter_endpoints`), a host's own
  index on one of the 14 tables, and rows do not count; the fix-up left
  the release value unchanged. Value for this release, after `Apply`:
  `924e777a63a110753483a2dd08fb61c19bc5b9f96f09271b1bd265b9212bd924`
  (CHANGELOG, `TestSchemaFingerprintRelease`).
- Tests (`store/migrations_test.go`):
  `TestMigrationsMatchApply` (list on one fresh database, `Apply` on
  another: same normalised `sqlite_schema` and fingerprint; `Apply` after
  the list moves nothing — fails when a step's column differs, checked),
  `TestMigrationsPin` (4 steps, last `v4`), `TestSchemaFingerprintRelease`,
  `TestSchemaFingerprintIgnoresOtherTablesAndRows` (a host table, a host
  index on `matter_fabrics` and rows leave it unchanged; an added column
  or a dropped declared index moves it),
  `TestSchemaTablesAreTheSchemas` (14 tables; dropping any moves the
  fingerprint), `TestMigrationsDown` (each Down restores the previous
  fingerprint; all Downs leave no matter_* object),
  `TestMigrationV3RebuildKeepsRows`, `TestApplyUpgradesEveryStep` (a
  database at any step, `Apply`'d, has the release fingerprint).

## Open questions — owner decisions (2026-10-12)

1. **Version cut.** The brief's cut (v1 = v0.2.0 DDL, v2 = four v0.3.0
   tables, v3 = rebuild) contradicts the CHANGELOG (`[0.2.0]` names
   `matter_groupcast_groups`, `matter_group_table`,
   `matter_server_subscriptions` and the group-key-map fix; `[0.3.0]` only
   `matter_ota_default_providers`) and the tags (`v0.2.0:store/schema.sql`
   already has the three tables and no foreign key). Decided: keep the
   four-step cut per the tags.
2. **Version format** `"v1"`…`"v4"`, release in comments, three fields.
   Decided: keep.
3. **Mixed label styles** (60 CamelCase next to 31 spelled out). Decided:
   keep CamelCase.
4. **v3 Down is lossy.** Decided: acceptable; documented in the step file
   and the `Migration` doc comment (done in f2cf782).
5. **Fingerprint scope.** A host index on a module table moved it.
   Decided: a fix — done in f2cf782 (declared objects only, read from the
   DDL; test added; value unchanged).
