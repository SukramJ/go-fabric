## Differences from the brief

1. **The Thread row has no host selection.** No `node.Config` field mounts
   the Thread NetworkCommissioning variant: the root mounts the Ethernet
   server or, with `Network.WiFiCommissioning`, the Wi-Fi one
   (`node/root.go:276-303`); `core.NewThreadNetworkCommissioning` is called
   only by `cluster/threadbr/threadbr_wire_test.go:51`, and the daemon's
   `--otbr` endpoint mounts no NetworkCommissioning. So the row is declared
   and in `node.AheadRows`, the node's root candidates are built from the
   configuration's NetworkCommissioning selection (never the Thread bit),
   and no disabled/enabled behaviour test exists for it. Its measurement
   builds the servers directly: `core.NewNetworkCommissioning` (what
   `node.New` mounts) against `core.NewThreadNetworkCommissioning` over a
   border-router stub that answers every call with an error.
2. **Line numbers.** `ThermostatFeatureMSCH` is at
   `cluster/thermo/thermostat_server.go:79`, not :80; the code cites the
   symbols. The register's line numbers in the brief are pre-edit; the
   contract bullet moved the table down six lines.
3. **Root decisions in `Node.Surface()`.** The root's decisions (one per
   selected ahead feature) open `Report.Decisions`.
4. **A custom `Remove` of a root feature is applied**: `composeRoot` copies
   `Config.TimeSynchronization` and clears the bit, so the decision is not
   a lie; the host's value is untouched (tested).
5. **Hex ids in the report too**: decisions and withheld elements carry
   their cluster (4 digits) and id (4 for a device type or cluster, 8
   otherwise, a feature's mask 8).
6. **Not-selected comparison**: the brief's "the S1 snapshot's lists" is
   held two ways — the regenerated snapshot equals the old one element for
   element (decoded old/new `surface.json`, only `policies` moved), and the
   behaviour tests compare the zero-value build with the build under every
   row enabled.
7. **Measurement reads** the Thermostat through `endpoint.ClusterSurface`
   of the device's server, TimeSynchronization through `Node.Surface()`'s
   root (itself `endpoint.SurfaceEndpoint` → `ClusterSurface`).
8. **`RefusedError.Is`** carries `ErrExtensionNotEnabled`, so `Unwrap()
   error` keeps its signature (no API break there).

## Decisions taken

- The demo thermostat's `schedules` bool is gone: it reads its options'
  policies, so `--extensions BD-chip-Thermostat-Schedules` serves MSCH as
  `--thermostat-schedules` does.
- The daemon threads one `Policies` value: `fleet.bridged` / `fleet.part`,
  `partOf(parent, …)` for parts the demo types build, and `newDemoMedia` /
  `newDemoBorderRouter` take it.
- `--extensions` is validated in `compose` (both the run and the dump path),
  before anything is opened.
- The register parser takes `surface` as an optional column; present, every
  row must read `yes` or `no` (a row problem `make ahead-check` reports).
- Hex widths: 4 digits for device type and cluster ids (as `Element.String`
  and the summary already render them), 8 for attribute, command, event
  ids and the FeatureMap.
- Policies digest domain `v2`, so the zero value's digest moves as the
  brief says.

## Left out

- Behaviour tests for the Thread row (difference 1).
- A gate for a host that supplies its own Thermostat server
  (`thermostatdef.Declare{HostServer: …}`): a host server is one cluster
  candidate whose features are its own (S1), so it is not tagged.
- No chip-tool fixture run: with and without `--thermostat-schedules`, the
  daemon built at `origin/main` and at this branch report equal effective
  surfaces; only the MSCH decision gains its tag.
- PICS `TSTAT.S.F07` and `TC_TSTAT_4_5` (concept F row S2): the case is
  absent at the harness commit; classified in `docs/certifiability.md`.
