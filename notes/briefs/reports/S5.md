## §2 `Profile` and the profile policy

`surface/profile.go`: `Confidence` (`Reproduced`, `Inherited`,
`Reported`; `String` spells them as the register does), `Effect`
(`EffectRemove`, `EffectWarn`, `EffectLevel`), `ElementPattern`
(`Kind`, `Cluster`, `ID`; `Matches`, `String` in the register's form,
the feature code read from `schema.ClusterFeatures`), `ProfileRule`,
`Profile`, `Profiles()`, `ProfileByName`, `ErrUnknownProfile`,
`ErrProfileLevelConflict`, `Policies.Profiles`, `Policies.LevelOrigin`,
`Policies.Report`. Each selected profile is a built-in policy
`profile:<name>` after `level`, before `Custom`:

- Reproduced `remove` rule matching → `Remove`, reason
  `removed by profile <name>: <Reason> (<Source>)`; the chain rewrites a
  mandatory element to `kept: mandatory at pin (removed by profile …)`.
- `warn` rule — or a `remove` rule of any other confidence (reachable only
  through the test seam; the generator rejects it) → `Keep`, reason
  `warning (<Confidence>) profile <name>: <Reason> (<Source>)`. Several
  warn rules of one profile on one element join with `; `.
- Level: `EffectiveLevel()` = explicit `Level`, else the level the
  selected profiles agree on, else the pin's. `Validate` fails with
  `ErrUnknownProfile` (naming the known profiles) and, without an explicit
  level, `ErrProfileLevelConflict` naming both profiles and their levels.
- `Digest()` gains one `profile\x00<name>` line per selected name (sorted,
  each once); an injected test profile adds its rules. The S2–S4 parts —
  extensions, effective level, custom policies — are unchanged; the domain
  stays `v2`, so the zero value's digest is unchanged
  (`fc6822f0…` in the snapshot).

`script/profilegen` reads the register (profile ids from the header's
column-contract sentence, rows from the `## Register` table) and writes
`surface/profiles_gen.go` (`make generate-profiles`). It imports `schema`,
never `surface` (the `levelgen` discipline), and fails naming the line on:
an unknown profile, an element that does not parse or is not in the pin's
schema (feature code via `schema.ClusterFeatures`, other kinds via the
level table at the pin), an unknown effect or confidence, an empty source
or reason, a `remove` or `level` row that is not Reproduced, a second row
of one profile for one element. Tests: `TestCellForms` (every cell form,
the escaped pipe, bold confidence), `TestRegisterRules` (29 failure
cases), `TestRegisterIsCurrent` (drift), `TestCommittedRegister` (the
brief's properties re-checked on the committed register, and
`surface.Profiles()` equals its rows exactly).

## §3 The daemon

`--profile name[,name…]` (`surfacePolicies`): an unknown name or a level
conflict stops it with `--profile: …` and the list of known profiles.
`--dump-surface` carries `profiles`, `level` and `level_origin`
(`explicit` / `profile <name>[, <name>…]` / `pin`) through the report.

## Differences from the brief

1. **`EffectiveLevel` stays exported** (since S3) and is extended; no
   unexported `effectiveLevel()`.
2. **`Report` gains `Profiles` and `LevelOrigin`** (JSON `profiles`,
   `level_origin`), filled by the new `Policies.Report()`, which device
   and node now start their reports with: the dump carries what it shows
   through the report.
3. **The cell parser lives in `script/profilegen`**, not in `surface`: the
   generator does not import the package it generates. The "parse every
   register cell form" tests are therefore `profilegen` tests; `surface`
   tests the pattern's matching and rendering.
4. **Profile ids come from the register's header** (the column-contract
   sentence), not from a list in the generator; every id is a profile,
   with no rule when no row names it.
5. **Test seam:** `internal/surfaceseam` (layer model-and-protocol,
   coverage floor 0 like the other seams) and
   `surfacetest.WithProfiles(p, profiles...)`, which makes the profiles
   known *and* selects them; an injected profile shadows a register one of
   the same name.
6. **Selection is canonical:** sorted and deduplicated for the chain, the
   digest and `Report.Profiles`.
7. **Digest domain not bumped:** without a profile the encoding is
   byte-identical to v2.
8. **The runtime policy also enforces Reproduced-only** (a non-Reproduced
   remove warns), beside the generator's rejection.
9. **A level row must be Reproduced** in the generator (question 1).
10. `make generate-profiles` added.

## Questions

1. May an Inherited or Reported row set a profile's level? Implemented:
   no — a level removes surface, so the generator requires Reproduced as
   for `remove`.
2. The register's Source and Reason cells are copied verbatim into the
   decision reasons, Markdown backticks included. Strip them?
3. A name selected twice is deduplicated silently. Should `Validate`
   reject it instead?
4. "Exactly one warning row" holds for the daemon's one MSCH thermostat; a
   host with several gets one row per endpoint. Intended?
