## What was built

### L1: timed commands from the model

- `contract.TimedCommander { IsTimedCommand(cmdID uint32) bool }`
  (`contract/matter.go`, stdlib only).
- `spec.Instance.IsTimedCommand` delegates to `Instance.IsTimed`
  (`cluster/spec/instance.go`). `spec.Server` gets it through embedding and
  has a compile-time assertion (`cluster/spec/server.go`). Every hand-written
  server that embeds `*spec.Instance` gets it too, among them the EVSE server
  in `cluster/energy/evse.go:175`, so that file was not touched.
  `closure.ControlServer` holds its Instance as a field, so it gets an
  explicit method (`cluster/closure/closurecontrol_events.go`).
- `im.TimedCommandProvider` (`im/dispatcher.go`) is implemented by
  `endpoint.TopologyDispatcher.IsTimedCommand` (`endpoint/dispatcher.go`).
  The resolved server answers when it implements `TimedCommander`;
  otherwise the dispatcher falls back to `schema.IsTimedInvoke`.
  `im.HandleInvokeRequest` asks the provider for a concrete-endpoint path.
  It uses `schema.IsTimedInvoke` for a wildcard-endpoint path or when the
  dispatcher has no provider (`im/invoke.go`).
- `schema/timed_gen.go` is generated by `script/generate_matter_schema.go`
  (`writeTimedFile`). It lists every request command whose `effective.access.timed`
  is true in `parity/schema.json`: 36 commands in 9 clusters.
  `schema/timed.go` now holds only `IsTimedInvoke` and its doc.
- Cited source: matter.js
  `packages/protocol/src/action/server/CommandInvokeResponse.ts:292-295`.
  In the local checkout `if (limits.timed && !this.session.timed)` is on line
  292 and the `return … NeedsTimedInteraction` on 294. The brief and the old
  comments said 291-294, and the comments now cite 292-295.

### L2: `Constraint.In`

- `spec.Instance.ValidateWrite` checks an "in" constraint after the type and
  bound checks (`inPeer`, `cluster/spec/write.go`). The value must be an
  entry of the peer attribute's current value, read through `Peers` by
  `AttributeByName(c.In)`. A non-list peer counts as a one-entry set. An
  unresolved peer is an empty set and refuses the value. This follows
  matter.js `packages/model/src/aspects/Constraint.ts:164-170` and differs
  from an unresolved bound, which admits. The refusal is CONSTRAINT_ERROR,
  as in matter.js `packages/node/src/behavior/state/validation/constraint.ts:153-163`.
- I deleted the hand-written membership checks in `localeSink`
  (`cluster/core/localization_configuration.go`) and `calendarSink`
  (`cluster/core/time_format_localization.go`). The runtime refuses before
  the sink is called, so the host sees the same behaviour: CONSTRAINT_ERROR,
  and OnWrite is not called. Two tests show this. The existing `cluster/core`
  refusal tests still pass, and `TestConstraintInParityMatterJS` checks that
  the sink sees one write (the member) and not the refused value.

### L3: TSUIC default from UnitLocalization

- New field `thermo.ThermostatUIConfig.UnitLocalization *spec.Server`.
  When `TemperatureDisplayMode` is nil, construction reads the server's
  TemperatureUnit once. Fahrenheit gives Fahrenheit; anything else (Celsius,
  Kelvin, or the field unset) gives Celsius. A configured mode wins. Source:
  matter.js `ThermostatUserInterfaceConfigurationServer.ts:16-28`, cited in
  the file comment that replaces the old :24-28 gap note.
- The daemon is unchanged. The brief's default: co-location is the owner's
  decision.

### L4: ModeSelect on the generated encoder

- `modeselect.Server` reads SupportedModes as
  `spec.List[ModeOptionStruct](copyModes(...))`. `ModeOptionStruct` is
  already an alias of the generated struct, so the value encodes through
  `msdef.ModeOptionStruct.EncodeTLV` via the bridge's `spec.Encodable` case
  (`bridge/application_values.go`).
- Deleted: the `case []mattermodeselect.ModeOptionStruct` in `bridge/reply.go`
  and the unexported `boundedList`, which had no other caller.
- The bounds follow matter.js: nothing is trimmed. `LabelMaxBytes`,
  `SemanticTagsMaxEntries` and `SupportedModesMaxEntries` stay exported. They
  are now documented as the host's part of the contract on
  `ModeSource.SupportedModes`, and the parity test holds them to the
  definition (`TestBoundsMatchTheDefinition`, which also covers the two
  struct-field bounds).
- Deprecated, because nothing reads them any more: `ModeOptionFieldLabel`,
  `ModeOptionFieldMode`, `ModeOptionFieldSemanticTags`,
  `SemanticTagFieldMfgCode` and `SemanticTagFieldValue`. They have a
  `Deprecated:` paragraph and are announced under a new `### Deprecated`
  heading in CHANGELOG.
- Wire fixture: new generator
  `notes/parity/matter/generate-modeselect-fixtures.ts` (it honours
  `MATTERJS_DIR`). Its master is
  `cluster/modeselect/testdata/modeselect-wire-fixtures.json`, produced by
  running it against the local built matter.js (`TlvOfModel(SupportedModes)`).
  The consumer is `cluster/modeselect/modeselect_wire_parity_matterjs_test.go`.
  The generator is also listed in `notes/parity/matter/README.md`.
- Wire change: SemanticTag MfgCode and Value now use the smallest integer
  width (fixture `supported_modes_small_ints`: `2400` for 0). The hand
  encoder always wrote them as two bytes. Label and Mode bytes are unchanged
  for in-bounds values.

## Left out, and why

- **Per-attribute timed write** (`BD-Matter-TimedAndQuotaDeferred`): still
  not built. 25 `Timed: true` entries exist in
  `cluster/spec/*/definition_gen.go`, and all of them belong to commands. No
  exposed attribute carries "T".
- **"in" on device-side values.** `Server.Set`/`SetAttributes`/`Initial`
  (`CheckValue`) do not check "in". The brief says "on writes". If they did
  check it, `NewServer` would refuse LocalizationConfiguration: `Initial`
  is checked in id order (`cluster/spec/server.go:149`), ActiveLocale (0)
  comes before SupportedLocales (1), and an unresolved peer refuses. matter.js
  validates every commit. This is a divergence for the owner to classify
  (see the questions).
- **matter.js `ModeSelectServer.ts:32-34, 88-95`** (CurrentMode, StartUpMode
  and OnMode must be members of SupportedModes): not in the brief's Must, not
  built, and I did not read those lines myself.
- **ModeSelect Description** is still bounded at encode time
  (`tlv.BoundedString`, `modeselect_server.go:284`). It is outside L4's three
  bounds.
- **Group invoke** (`bridge/group_messaging.go:312`) still passes
  `schema.IsTimedInvoke`. It now covers every "T" command of the snapshot,
  but it does not ask a server.

## Open questions

1. **Breadth of `TimedCommander`.** It is implemented on `spec.Instance`,
   not only on `spec.Server`, so every server embedding an Instance answers
   from its definition. The brief said "implemented by `spec.Server` through
   `Instance.IsTimed`". Is the wider placement acceptable? The answer is the
   same as the generated table, which comes from the same snapshot.
2. **Behaviour change from the generated table.** These now answer
   NEEDS_TIMED_INTERACTION when invoked untimed, including from a
   hand-written server that falls back to the table:
   - DoorLock Toggle, UnlockWithTimeout, SetUser, ClearUser, SetCredential,
     ClearCredential, Set/ClearAliroReaderConfig
   - all seven EnergyEvse requests (Disable … ClearTargets, GetTargets
     included)
   - ClosureDimension SetTarget and Step
   - ThreadBorderRouterManagement, ThreadNetworkDirectory, AccountLogin and
     ContentControl commands

   Each comes from `effective.access.timed` in the snapshot. Docs to update:
   `docs/open-items.md:62` ("timed.go omits eight DoorLock requests") is now
   out of date.
3. **"in" and device-side values**: classify the write-only evaluation as
   by-design, or extend it. Extending it would need an order-aware `Initial`
   check.
4. **The deprecation release number.** The marker and the CHANGELOG entry
   say "the second minor release after the one that ships this marker",
   because no source names the next release. README §API stability asks for
   the release by number. Please set it (v0.5.0 if the next tag is v0.3.0).
5. **A gap in `deprecation_policy_test.go`.** `TestDeprecatedIdentifiersAreAnnounced`
   finds the identifier on the line after the marker. For a `const (` group
   its regex matches nothing, so the five deprecated constants pass the
   check without being checked. They are announced in CHANGELOG anyway, but
   the guard does not see a grouped deprecation.
6. **`TestTimedInvokeParity` (`schema/timed_test.go`) skips in a worktree**,
   because it looks for `../matter.js` beside the module root. I extended its
   DoorLock row to the full 11-command set with `fullCoverage: true`. I
   checked those 11 against
   `door-lock-cluster.element.ts` (:230, 234, 237, 241, 427, 490, 499, 553,
   560, 566, 576; id and access are in each header object, so the test's
   parser reads them) but did not run the test against the checkout. Please
   run it once from the main checkout.
