## §6 The owner's hand tests (open)

- **Group multicast against a real controller.** These are the steps from `notes/manual-test-plan-0.4.0.md` C5:
  1. Pair a second real device.
  2. Run `group create 257 --key random --nodes <a>,<b> --endpoints 1`.
  3. Run `group send 257 OnOff/Toggle`.

  Expected: both devices switch together. A device older than Matter 1.5 has no Groupcast, and the controller falls back to KeySetWrite, AddGroup and ACL. The comparison's next-thing item 1 names the chip-tool variant: `groupcast join-group`, a multicast `onoff toggle`, `groupcast leave-group`.
  Result: open.
- **ESPHome proxy live test.** From `docs/guides/ble-proxies.md` §The reference controller:
  1. `cd ble/esphome && go build -o reference-controller ./cmd/reference-controller`
  2. `./reference-controller pair --bluetooth-proxy <proxy>,$KEY --code <QR> --wifi-ssid <SSID> --wifi-credentials <pw>`, or `--bluetooth-proxy-discover --bluetooth-proxy-key <name>=$KEY`.

  The proxy must be taken from Home Assistant while the pairing runs (one subscriber per proxy). Result: open.
- **Apple Home camera pairing.** This is the ecosystem gate in `docs/guides/camera.md`: no host device carries a camera cluster until a live test with Apple Home has passed. No guide gives steps for it, so the owner defines them. Result: open.
- **CSA Test Harness spot check** (the proof column of phase 27): not run. It is the owner's.
