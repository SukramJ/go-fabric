## Differences from the brief

1. A device's effective surface (and so the node's bridged endpoints and
   the snapshot) holds the device's own servers and its own device type
   only — not the assembler's clusters (Descriptor, BDBI, Identify, Groups,
   ScenesManagement, Binding), not measurement-projected clusters, not the
   BridgedNode device type. The equality test compares cluster by cluster
   and requires the rest of the wire to be those.
2. The effective surface is read in `New` after the hooks are installed,
   not inside `compose`; measured cluster ids reach `compose` through
   `settings.measured`, so the signature stays `compose(t, s, opts)`.
3. Parts: `Node.Surface` and the `Add` check walk `Spec.Parts`.
4. Additional exported API: `surface.Describer` (the "stable
   description" in `Policies.Digest`), `Clone` on `Surface`, `Endpoint`,
   `Report`, `String` on `Element`/`Change`, text marshalling of the enums,
   `node.AggregatorSurfaceKey`, the four `endpoint` functions.
5. `--dump-surface` prints the canonical JSON laid out for review (flat
   objects on one line); `json.Compact` of it is byte-identical to
   `MarshalJSON` (tested).
6. The handover's "Current state" section is stale (wave 5); the line went
   to its top.

## Decisions taken

- `Kind` and `Origin` start at 1 (zero = none); `Verdict` `Keep` = 0.
- A `Keep` with a reason is a decision row (the policy spoke); only a
  silent element gets the `Policy ""` row.
- Feature `Mandatory`: type-mandated, cluster "M", or the selection
  without that one bit fails `spec.CheckFeatures`. Element `Mandatory`:
  type `PresenceMandatory`, or conformance mandatory at the selection
  (then `OriginClusterMandatory`). Declared element candidates are what
  enters `spec.Options` (`s.elements`, `s.implied` incl. typed `Initial`
  keys); an untyped `Initial` adds no element and is no candidate.
- `OriginKitDefault` carries no candidate: the only paths that add an
  element to a default server's options are those above
  (`device/device.go` `defaultServer`); `powerSourceDefaults` and
  `initializeDefaults` set values only.
- A removed cluster drops its declaration's hooks (else `attachHooks`
  would refuse the device).
- `Diff`: an endpoint or cluster only one side has is one change per
  device type / cluster; Before/After are "revision N", "set", "served",
  "accepted", "generated".

## Questions

1. Should the surface cover what the assembler mounts (Descriptor, BDBI,
   Identify, Groups, Scenes, Binding, BridgedNode device type,
   measurement clusters) — by reading the assembled topology, or by a
   dry assembly? Today the snapshot does not see a change there.
2. ADR 0030 decision 7 says whole clusters are not gated; brief §2 has a
   `Remove` of an opted-in optional cluster honoured. Implemented per the
   brief; is decision 7 about the built-in policies only?
3. `"aggregator"` can collide with a device whose key renders the same (a
   node test uses that key). Reserve it, or another key?
4. Mandatory is judged per single removal: removing two bits of an "at
   least one" group, or a feature a declared element depends on, fails
   `New` with `ErrConfiguration` from the spec check, not as a decision.
   Acceptable for S1?
5. The JSON carries ids as decimal numbers; hex strings would read better
   in review diffs, at the cost of a custom codec. Preference?
