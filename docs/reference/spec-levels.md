# Specification levels

A **specification level** is a Matter revision matter.js has shipped a
release for. A host selects one with `surface.Policies.Level` (the
reference daemon: `--spec-level`); the built-in level policy then composes
every device as that revision's model knows it — while the behaviour, and
every `ClusterRevision`, stay the pin's
([ADR 0030](https://github.com/SukramJ/go-fabric/blob/main/docs/adr/0030-the-served-surface-is-a-value-under-policies.md),
decision 5). The zero value of `Level` is the pin's level and changes
nothing.

What exists at each level is generated from matter.js's tagged releases,
whose `Specification.REVISION` names the revision each tag models:
`script/extract-levels-from-matter-js.ts` reads the tag's `@matter/model`
into `parity/levels/<level>.json` (`make generate-levels`, a review
decision like the main snapshot), and `script/levelgen` writes
`schema/levels_gen.go` and the generated block below. connectedhomeip's
data model XML is never the source; `internal/chipdm` compares the level
files with `data_model/<level>` at test time
([ADR 0015](https://github.com/SukramJ/go-fabric/blob/main/docs/adr/0015-chip-data-model-read-at-run-time.md)).
Levels below 1.4 are out of scope: the device layer's own device types
start at the pin, and 1.3 predates every bridge this module serves.

How the level policy decides, per endpoint:

1. A device whose device type, or a cluster its type mandates, the level
   does not know is **withheld**: `device.New` returns a
   `*surface.WithheldError` (`errors.Is(err, surface.ErrWithheld)`) with
   the report, `node.Aggregator.Add` of it returns the same error and the
   node's `Surface().Withheld` lists it. The node runs on.
2. An optional cluster, feature, attribute, command or event the level
   does not know is **removed**.
3. One the pin mandates is **kept**, with the reason
   `kept: mandatory at pin (absent at level <L>)`.
4. When the removals leave a feature selection the pin's conformance
   rejects, features are re-added, smallest bit first, with the reason
   `kept: feature selection invalid at pin without it`.
5. BridgedDeviceBasicInformation's `ConfigurationVersion` is never removed
   (the hand exception below).
6. An element a hand-written server chooses itself is kept with the reason
   `kept: server-internal, not level-controlled`; the last section lists
   those of the reference daemon.

`script/levelgen` writes this page's generated block; a test fails when it
is stale.

## What each level does not know

Computed from the level files. A device whose type, or a cluster its type mandates, is
absent at the level is **withheld**; an optional cluster, feature, attribute, command or
event absent at the level is **removed**, unless the pin mandates it. *Kept, mandatory at
the pin* lists the attributes, commands and events whose own conformance at the pin is
unconditionally mandatory (`M`, or `Rev >= vN` at the cluster's revision) and that the
level does not know, on clusters it knows; a composition also keeps what a device type
or the feature selection mandates, which only the composition can tell.
